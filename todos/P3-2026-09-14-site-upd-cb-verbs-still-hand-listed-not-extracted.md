# Two eas colon-verb families predate the source-extraction mechanism and were not retrofitted

## Summary

`.claude/hooks/repro-outward-cli-corpus.sh`'s `SITE_UPD_VERBS` and `SITE_CB_VERBS` arrays (PR
#935) hand-list the branches of two guard alternations — `eas update:(delete|edit|republish|
revert-update-rollout|roll-back-to-embedded|rollback)` and `eas (channel|branch):(create|edit|
delete|rename)` (both in guard-outward-cli.sh). Coverage is complete today (every branch has
a row), so this is not a live gap. But it is the exact "hand-carved subset" shape the newer
`_alt_or_die`-based "DENY-SITE COVERAGE, ALTERNATION BRANCHES" axis (added
2026-09-14, todos/archive/P2-2026-09-08-corpus-covers-deny-sites-but-not-their-alternation-branches.md)
exists to eliminate for four OTHER regexes — a branch added to either of these two guard
alternations later needs a human to remember to extend the hand-list, or it goes uncovered
invisibly, same as the 13-branch finding that todo measured.

## Background

Found by code-reviewer during that todo's review round 1: "the `eas update:(...)` site ... and
the `eas (channel|branch):(...)` site ... are also literal-branch alternations of the identical
source-extractable shape (one is even a two-group alternation, same shape `_alt_or_die` already
handles for the railvar/railsvc checks) — yet their corpus coverage ... is still hand-typed, not
generated by `_alt_or_die`." Judged out of that todo's scope (four specific regexes named by its
own table) and deferred here rather than folded in under time pressure, per the reviewer's own
offered alternative ("name them explicitly as deliberately left hand-listed, or fold them into
`_alt_or_die` in the same pass") — this todo is the fold-in.

## Implementation Notes

**Where.** `.claude/hooks/repro-outward-cli-corpus.sh`, the `SITE_UPD_VERBS`/`SITE_CB_VERBS`
declarations and their generation loops (a few hundred lines above the newer
"DENY-SITE COVERAGE, ALTERNATION BRANCHES" axis this todo generalizes from). Reuse `_alt_or_die`
— do not write a second extraction helper.

**The SITE_CB_VERBS two-group shape.** The guard line is
`eas${_OUT_SEP}(channel|branch):(create|edit|delete|rename)${_OUT_POS_SUFFIX}` — TWO
alternations in one line, joined by a literal `:`. The existing nested loop
(`for n in channel branch; do for v in "${SITE_CB_VERBS[@]}"; do ...`) already treats them as
two independent axes; only the SOURCE of each list needs to change from a hand-typed array to an
`_alt_or_die` extraction. Verify the extraction pattern does not also accidentally match the
`eas${_OUT_SEP}update:(...)` line above it (different literal text between the tool word and the
first group — `update:` is not `(channel|branch):`).

**Runtime impact.** None expected — this changes HOW the same rows are produced, not the row
count. State the measurement in the PR rather than assuming it, per this file's own standing
convention.
