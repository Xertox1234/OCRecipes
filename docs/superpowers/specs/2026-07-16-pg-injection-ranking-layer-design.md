## Question this spec answers

Should the doobidoo-style relevance-ranking layer (exponential time decay, git-aware boosts, quality scoring, phased injection budget — research report R2) be built on top of `inject-patterns.sh`, and if so, in what form? R2 called this the highest-value item. This spec evaluates that claim against 11 days of real telemetry and the hook as it exists today, not as it existed when R2 was written.

## Evaluation definition (binding on any revival)

The gate any revived ranking layer must pass before its behavior flip — defined now so a future session cannot substitute vibes:

1. **Corpus:** N = 200 events sampled from `harness.injection_log`, stratified by domain, `injected` events weighted over `pointer` (pointers carry no selection). Each event supplies `(edited_path, domain, ts, doc_paths)`.
2. **Replay:** for each event, recompute selection under (old) the live pipeline and (new) the candidate ranking, against the corpus as of the event's `ts` (filter `docs/solutions/` by each file's dated filename ≤ ts — a deliberate approximation that reads current frontmatter and ignores post-creation `tags:`/`applies_to:` edits; acceptable because both sides of the replay share the same approximation, so the diff is unbiased).
3. **Judgment:** human-judged relevance on the **diff only** (events where old ≠ new selection), blind to which side is which: for each changed event, "which list better serves the edit at `edited_path`?" — better / worse / equivalent.
4. **Thresholds:** ship the flip iff changed-event rate ≥ 5% (below that the layer is a measurable no-op → auto-drop), new judged better in ≥ 60% of changed events, and worse in ≤ 10%. Anything else → drop again, permanently.

## DECISION: DROP — with explicit re-triggers

**Drop the ranking layer.** Reasons:

1. **The premise is stale.** R2 targeted an unranked hook; the live hook already ranks by file-specific relevance (applies_to), recency (newest-first), defect class (bug slot), domain stakes (domain_rank), and enforces a real budget with lossless deferral. Most of R2's value shipped piecemeal in June–July without a scoring formula.
2. **The residual signals don't survive scrutiny.** Standalone decay is order-equivalent to what exists; quality regexes police a failure mode (uncurated capture noise) this corpus structurally cannot have; phased budgets solve a 2.6%-frequency, already-lossless problem.
3. **The one live candidate (git-aware boost) has no demonstrated miss to fix.** Nothing measures whether injected refs are even read (read-through telemetry does not exist), so its eval could only measure plausibility — insufficient grounds to touch the hottest hook path where, per this todo's own risk note, wrong ranking is worse than no ranking.
4. **Opportunity cost.** The corpus-health problem the telemetry _does_ surface (116/671 docs ever delivered; dead weight) is a pruning/telemetry question, already owned by the usage-telemetry line, not a ranking question.

**Re-triggers — any one reopens this line, inheriting this spec's architecture (manifest generator), rollout (shadow-first), and evaluation gate verbatim:**

- Deferral share > 10% over any rolling 30-day telemetry window (budget pressure becomes real), or
- Corpus > 1,300 docs (newest-first starvation of older domains becomes acute), or
- Read-through telemetry lands and shows injected refs systematically unread while grep-pulled older docs dominate actual usage, or
- Deliberate user choice to run the git-boost shadow experiment.
