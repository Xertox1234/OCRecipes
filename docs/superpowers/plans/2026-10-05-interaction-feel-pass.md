# Interaction-Feel Pass — Plan & Checklist

**Origin:** 2026-10-05 read-only interaction-feel audit (4 `mobile-reviewer` slices: scan→log, Home/Plan, Coach/chat, Profile/forms) against the inventory in `.claude/skills/interaction-feel/SKILL.md`. User complaint: "UI interactions are flat and unexciting."

**Diagnosis:** the motion/haptics infrastructure exists (`client/constants/animations.ts`, `client/hooks/useHaptics.ts`, `useSuccessPop` in `client/hooks/useSuccessAnimation.ts`, reduced-motion gating) — screens just don't use it. Fix by **extending shared primitives first**, then adopting at call sites.

**Process per PR:** feature branch (never main), strict TDD, one PR per checklist step, `interaction-feel` skill inventory walked for every touched element, reduced-motion gated, motion configs as named exports in `animations.ts` (no inline `{damping, stiffness}`), haptics only via `useHaptics()`. React Compiler active — no manual `useCallback`/`memo`. Verify visually with `verify-ui` where device-shaped.

**Workspace:** worktree `.claude/worktrees/interaction-feel-pass`, branch `feat/interaction-feel-pass` (contract declared). This plan file is gitignored (`docs/superpowers/`) — it lives only here; copy to the main checkout's `docs/superpowers/plans/` before removing the worktree. `node_modules` is a symlink to main (never `npm install`); `.env` is ABSENT (Agent-style worktree) — client tests shouldn't need it; anything server/DB-backed may false-red. Per-step PRs: branch each step off `origin/main` inside this worktree (`feat/interaction-feel-<step>`).

## Verified baseline (2026-10-05)

- `successPopConfig`/`useSuccessPop` used only by `client/components/RecipeActionBar.tsx`.
- 89 of 135 client `.tsx` files rendering `Pressable`/`Touchable*` have no pressed-state signal (no spring, ripple, or `pressed` reference) — FILE count, not element count.
- Zero haptics in `Toast.tsx`, `context/ToastContext.tsx`, `Chip.tsx`, `Button.tsx`, `Card.tsx`.
- `Button` (0.98) and `Card` (0.98, when `onPress`) and `Chip` (0.95, when `onPress`) already press-spring automatically. `Chip.selected` swaps style instantly, no haptic.
- No `withRepeat` anywhere in coach/chat files — no animated typing indicator exists.
- Only `onboarding/PreferencesScreen.tsx` of the onboarding screens uses `useHaptics`.
- No validation shake anywhere. No generic list-row/settings-row primitive.
- NOT a finding: `useSuccessPop`'s direct `Haptics` call is deliberate and documented.
