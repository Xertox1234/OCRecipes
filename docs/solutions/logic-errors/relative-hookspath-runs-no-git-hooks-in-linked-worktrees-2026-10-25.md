# husky's relative core.hooksPath runs no git hooks in a linked worktree

## Problem

`.git/config` is shared by every worktree, and husky 9 writes `core.hooksPath = .husky/_` (relative) to
it on every `npm install`. Git resolves a relative hooksPath against **each worktree's own root**.
`.husky/_` is generated by husky and gitignored (its own `.gitignore` is `*`), so a linked worktree that
never ran npm install has no such folder. Git then silently runs **no hooks** there: no lint-staged,
no pre-push `preflight:fast`, no pass-stamp, and the PR-preflight guard denies.

Measured over transcripts since 2026-10-12: 5 of the 8 PR-stamp denies after #1436 were pushes from
`.claude/worktrees/*` with no gate output at all. The 2026-09-25 "no hooks" and 2026-09-26 "hooks ran"
reports in memory were this value flipping between relative and absolute.

## Symptoms

See frontmatter. The deny's `found:` sha belongs to another session's earlier push, not this one.

## Root Cause

- `git rev-parse --git-path hooks` from a worktree prints `.husky/_`, relative to that worktree.
- A throwaway repo on git 2.50.1 reproduces it. With the relative path, a worktree commit runs no hook.
  With an absolute path to the main checkout's `.husky/_`, it runs.

A second, separate cause of retries: PreToolUse hooks run **before** the command, in Claude Code's own
environment, so `SKIP_PR_PREFLIGHT=1 gh pr create …` never sets the variable the guard reads. Three
retries tried that because the deny message said only "Emergency bypass: SKIP_PR_PREFLIGHT=1".

## Solution

- `prepare` runs `scripts/install-git-hooks.sh`. It runs husky, then sets
  `core.hooksPath = <main checkout>/.husky/_` (absolute), but only when those shims exist.
  - It points at the main checkout, not the cwd, so an install run inside a worktree cannot leave
    every checkout aimed at a folder that goes away with that worktree.
  - Worktrees then run the main checkout's copy of `.husky/pre-push` (husky's `h` finds the hook next
    to the shim folder).
- `pr-preflight-guard.sh`'s deny adds "Git runs no pre-push hook in <tree> … run
  `npm run preflight:fast` here" when `[ ! -x "$(git rev-parse --git-path hooks)/pre-push" ]`.
  `--git-path` applies git's own resolution, including from a subfolder (`../.husky/_`).
- The bypass hint says to set the variable in the environment Claude Code was launched from, and that
  a prefix on the command does not reach the hook. What the guard accepts is unchanged.

## Prevention

- After any change to hook installation, check from inside a worktree:
  `git rev-parse --git-path hooks` should print an absolute folder holding an executable `pre-push`.
- A hook's bypass message must say **where** to set the variable. For PreToolUse hooks, a command
  prefix is never the answer.
