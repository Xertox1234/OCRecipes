# Hooks Rules

- Destructure `.mutate` (not the whole mutation object) for `useCallback` deps — the full mutation object is a new ref every render, defeating memoization
- Never list streaming state (`streamingContent`, `statusText`, `streamBlocks`) in `FlatList` `renderItem` `useCallback` deps — use `ListFooterComponent` instead; streaming deps cause full FlatList re-render on every token (~20×/sec)
- Values that change over time (phase, reducedMotion, etc.) used inside a zero-dep `useCallback` must be mirrored to a ref: `const fooRef = useRef(foo); useEffect(() => { fooRef.current = foo; }, [foo]);`. EXCEPTION — when the ref backs a SYNCHRONOUS guard read in a user-event handler (e.g. an `if (busyRef.current) return;` freeze), write it where the source changes, not via `useEffect`: the effect runs post-paint, so the render that flips the source state leaves a one-frame window where the handler still sees the stale value. For local state, wrap the setter (`const setX = useCallback((v) => { xRef.current = v; setXState(v); }, [])`) and route every write through it (list it in consumers' deps: `exhaustive-deps` only knows a raw `useState` setter is stable). Do NOT assign `xRef.current = x` in the component body: React Compiler rejects it (`CompileError: Cannot access refs during render`) and opts the whole component out. Only when the source is not yours to wrap (e.g. `busyRef.current = isPending` from a mutation) is a render-body write acceptable, and it costs that component its compiler coverage — say so in a comment. The `useEffect`-mirror is correct only when the ref is read later (in another effect or an async callback), where the one-frame lag is invisible.
- Effect cleanup must capture timer/subscription refs at cleanup time (inside the effect return), not at setup time — closures capture stale values
- `cancelAnimation` must be called when `reducedMotion` toggles at runtime — `withRepeat` animations don't stop on their own; use `else` (not `else if`) for the cancel branch to avoid dead zones
- Before listing a value in an "unmount-only" cleanup effect's deps, confirm it can ONLY change at mount/unmount — a value that also changes during normal use (e.g. `conversationId` set immediately before an async send, no `await` between) reruns that cleanup mid-life too, not just at unmount, and can abort a resource that just started. Mirror it to a ref instead, same as any other value the cleanup needs fresh. See `docs/solutions/logic-errors/unmount-only-cleanup-effect-dep-reruns-mid-life-2026-09-29.md`
- A hook storing ephemeral cross-screen state via `queryClient.setQueryData` (never fetched through `useQuery`) must pin `gcTime: Infinity` via `setQueryDefaults` before the first write — an unobserved entry's gc timer is scheduled once, never rescheduled by later writes, and the default 5 min can silently drop it early. Also never write `undefined` expecting a clear: `setQueryData(key, undefined)` is a no-op that leaves stale data in place — write `{}` instead. See `docs/solutions/design-patterns/query-cache-as-ephemeral-client-store-2026-09-29.md`
- **React Compiler discards a `useMemo`/`useCallback` dependency the callback body never reads** — it derives reactivity from what the callback reads, not the array literal, so a dep used purely as a recompute "trigger" compiles to a compute-once-forever cache and silently reintroduces the staleness bug it was meant to fix (Vitest doesn't run the compiler, so the test suite stays green while a compiler-covered build stays broken). Coverage is per-file and must be verified, not assumed from the flag: ONE unsupported construct (e.g. a `try`/`finally`) opts the whole component out, and in an exempt file every manual memo is instead load-bearing. Use `useState` + a ref tracking the previous trigger + a `useEffect` that reads the trigger instead — `useEffect` keeps a real, separately-tracked deps array regardless of what the body reads. See `docs/solutions/conventions/react-compiler-discards-unread-usememo-dependency-2026-09-02.md`
- A component a hook returns with a stable identity (`useMemo(() => function Stable() {…}, [])`, e.g. `useConfirmationModal`) must draw from its OWN state or a subscription it owns — never from a ref read during render plus a forced host re-render. A host compiled by React Compiler caches `<Stable />` on that never-changing identity and never re-renders it, so the child freezes on its first render (a blank sheet), even when the hook's own file is skipped by the compiler. Push new data into the child's state (it registers its setter in an effect). See `docs/solutions/logic-errors/hook-returned-stable-component-reading-ref-goes-blank-under-compiled-host-2026-10-01.md`
