# Database Rules

- Never use `onConflictDoNothing({ target })` with partial unique indexes — omit the target arg entirely (PG rejects at runtime). Use `onConflictDoUpdate` for cache tables, not `onConflictDoNothing` — the latter silently skips expired-entry updates and the stale row crashes a `!`-assertion.
- Always pair `.default([])` with `.notNull()` on array columns — `.default([])` alone keeps the TS type `T[] | null` and crashes on legacy NULLs. EXCEPTION — safety/correctness-critical derived columns must be NULLABLE with no default: `[]` cannot distinguish "derived, genuinely empty" from "not yet derived", so a `[]` default fails OPEN between migration and backfill. `null` = not derived (predicate treats it as unsafe); `[]` = derived and empty; write paths always store a concrete array. See `docs/solutions/conventions/nullable-not-empty-for-derived-safety-columns-2026-05-17.md`
- Derive the `Insert` type for a table with a NULLABLE typed `jsonb` column from `typeof table.$inferInsert` — NOT `z.infer<typeof createInsertSchema(table)>`: drizzle-zod 0.7.x loosens a nullable `.$type<>()` jsonb column to a generic `Json` union, breaking `.values()` type-safety
- Polymorphic FK always carries a discriminator column (e.g. `recipeType`) alongside the FK — never a bare `recipeId`. Polymorphic batch fetch: collect IDs first, batch with `.inArray()`, resolve with a `Map` — never loop-query
- Never store large blobs (images, receipts > 1 KB) in DB columns — use object storage (Cloudflare R2)
- Multi-phase background jobs: the eligibility query must catch phase-1-complete + phase-2-incomplete as a retriable state, not a dead end
- Inside transactions run parallel queries with `Promise.all`, never sequential `await`. Never re-query after an insert to build the response — construct it from the insert params + returned id
- Replace-by-DELETE-then-INSERT: dedupe the input with `[...new Set(ids)]` before insert when removing `onConflictDoNothing` — DELETE alone does not prevent duplicate-row failures on a `(userId, x)` unique constraint when caller-supplied ids repeat
- Never accept a filter parameter in a storage function's signature that the SQL does not consume — a silently dropped filter causes downstream personalization/label bugs
- Never interpolate a JS array into a raw `sql` template inside `ANY()`/`IN (...)` — it binds as a scalar and PG throws "malformed array literal"; use `inArray(col, arr)` from `drizzle-orm`
- `CURRENT_TIMESTAMP`/`now()` return transaction-start time — tests needing distinct `createdAt` ordering within one transaction pass explicit `new Date(baseTime - N)` values, never `setTimeout` between inserts. `TIMESTAMP WITHOUT TIME ZONE` drops offset info on round-trip — storage-layer recency assertions use a 24h-tolerant `Math.abs(stamp - Date.now()) < 24*60*60*1000` (catches hardcoded-epoch regressions, survives 14h TZ drift); tight request-window checks belong in route tests
- Never persist a caller-computed aggregate (count, level, average) or a per-row derived value (a boolean/classification computed by comparing the new row against existing siblings) from a pre-transaction read — two concurrent requests compute from the same stale snapshot and lost-update each other. Take an advisory lock as the first statement in the transaction, then: for an aggregate, RECOMPUTE it from the source rows AFTER the mutating insert and return it (a lock alone serializes the writes but still persists the stale value); for a per-row value, SELECT the comparison candidates under the lock BEFORE the insert, compute from that snapshot, insert with it — the storage fn drops the caller-supplied parameter and returns the computed value. See `docs/solutions/design-patterns/recompute-aggregate-under-lock-2026-05-17.md`
- Never cast `db.execute(sql\`...\`)`results via`as T`or`execute<T>(...)`alone — compile-time-only assertions on`Record<string, unknown>[]`; Zod-parse `result.rows[0]` against the table's inferred select schema to catch schema drift at runtime
- A one-shot prod-ops script with a destructive/irreversible DB write (backfill, mass `UPDATE`, column drop) gates the write on an explicit opt-in CLI flag (`--allow-prod-backfill`, like `seed-recipes.ts`'s `--allow-prod-seed`) — NEVER on `NODE_ENV === "production"`: `railway run` does not set it, so the guard never fires. Make idempotency the WHERE clause (`WHERE col = false`), report `.returning().length` as the affected count, and `isMain`-guard `main()` so tests can import the helpers. See `docs/solutions/conventions/prod-ops-script-guard-on-flag-not-node-env-2026-06-20.md`
- Merge a migration PR only once a prod `to_regclass` shows it: `docs/solutions/best-practices/prod-migration-merge-needs-a-query-2026-10-11.md`
- Every caller of a day-bucketed read (`getDailySummary`, `getDailyLogs`, anything on `getDayBounds`) passes a timezone — never let the `tz = "UTC"` default apply on a user-specific surface. Request paths: `parseTimezone(req.headers["x-timezone"])` threaded through the service (the client sends `X-Timezone: getDeviceTimezone()` AND keys the query cache by tz); background jobs: the stored `users.timezone`, resolved BEFORE the first day-bucketed call. For "today", omit the date param and bucket the now-instant in tz — a `?date=YYYY-MM-DD` string parses as a UTC-midnight instant and buckets the previous local day for UTC-negative users. See `docs/solutions/conventions/timezone-day-bucketing-threading-2026-06-10.md`
