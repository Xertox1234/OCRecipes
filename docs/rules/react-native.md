# React Native Rules

- Never pass functions or callbacks as route params — use event params or navigate + read-and-clear in `useEffect` (non-serializable params break state persistence and deep links)
- Always call `navigation.goBack()` immediately after `navigation.navigate()` when dismissing a `fullScreenModal` — `navigate()` alone leaves the modal on the stack
- Touch targets must be ≥ 44pt — add `hitSlop` for small controls (e.g., `hitSlop={{ top: 8, bottom: 8, left: 8, right: 8 }}`)
- Always add `insets.bottom + Spacing.X` to the last-item padding in scrollable lists — bare `Spacing.X` clips content behind the home indicator on notched devices
- `KeyboardAvoidingView` behavior: `"padding"` on iOS, `"height"` on Android — never `undefined`
- Always spread `FLATLIST_DEFAULTS` from `@/constants/performance` on every `FlatList` component
- Camera: always set `isActive={isFocused}` on `CameraView` — stops the camera when navigating away
- Mic: always call `stopListening()` in session reset/cleanup — leaving it open mutates state after the component is gone
- `Alert.prompt` is iOS-only — always guard with `Platform.OS === "ios"` and provide a `TextInput` fallback for Android
- Never gate `Linking.openURL(httpUrl)` behind `Linking.canOpenURL` — `canOpenURL` returns false on iOS for HTTP(S) without `LSApplicationQueriesSchemes` entries and blocks legitimate links. Call `openURL` directly and `try/catch` the failure instead
- A deep-link target screen must distinguish an **omitted** id param (the in-app create flow) from a **present-but-invalid** one. `linking.ts` `parseIntOrZero` coerces a malformed path segment to `0` (and does not clamp negatives — a `-5` path segment parses to `-5`, so "malformed" is "present but not a positive integer", not just `=== 0`), so deriving create-mode from a falsy check (`!entryId`) treats a bad link as "create" → it silently opens a blank create form and a save spawns a duplicate. Derive create-mode from `param === undefined`, and for a present id that doesn't resolve render a **load-aware** not-found state (gate on the list query's `isLoading`/`isPending`, not just `!entry`, or it flashes not-found while loading). The malformed-id guard must also live INSIDE every side-effecting handler the id can reach, not only in the render branch: a mount/param-driven effect (e.g. a cross-tab auto-send-on-open) can invoke a create/send handler independently of what JSX is currently shown, and unparsed deep-link query params land in `route.params` unfiltered (see `linking.ts`'s `Scan`/`verifyBarcode` comment) — so a malformed positional id and a triggering query param (e.g. `chat/abc?initialMessage=hi`) can arrive together and reach the handler even though the not-found view is what renders. Precedent: `client/screens/NotebookEntryScreen.tsx` (H4, 2026-05-29 reliability audit); `client/screens/ChatScreen.tsx` (M16, 2026-09-23 front-end audit) for the handler-level guard.
- A `beforeRemove` discard guard fires for the screen's OWN forward navigation too (`replace` removes the screen) — whitelist each intentional removal by `e.data.action.type` + payload target before `preventDefault()`, or the primary flow shows the discard confirm and can wipe state the destination reads. See `docs/solutions/logic-errors/before-remove-guard-intercepts-own-replace-2026-06-10.md`
- Scrollable screen content under a transparent header (`useScreenOptions()` defaults `headerTransparent: true`) must get its top inset from `useHeaderContentInset()` (`client/hooks/useHeaderContentInset.ts`) — or the `ScreenScrollView` wrapper (`client/components/ScreenScrollView.tsx`) for plain-`ScrollView` screens — instead of importing `useHeaderHeight` directly and hand-rolling `paddingTop` math. Never use an iOS-only prop (`contentInsetAdjustmentBehavior`, `contentInset`, etc.) as the sole fix — it no-ops on Android and leaves the identical hidden-first-row bug live there. See `docs/solutions/logic-errors/ios-only-scroll-inset-prop-leaves-android-header-overlap-2026-07-02.md`.
- A function imported from another module and called inside a Reanimated worklet body (`runOnUI`/`scheduleOnUI`, `useAnimatedStyle`, `useAnimatedScrollHandler`, a Gesture builder callback, etc.) needs its own `"worklet"` directive as the first statement — the Babel plugin does not workletize across `import` edges, so a missing directive is a silent app close in release/OTA builds despite `tsc`/ESLint/unit tests all passing. Enforced by the static guard in `scripts/__tests__/worklet-directive-guard.test.ts` — its `WORKLET_CALLBACK_HOOKS` set is name-keyed, so adding a new worklet-scheduling entry point (a rename, a new API) must add its name there too, or the guard silently stops inspecting it. See `docs/solutions/runtime-errors/reanimated-worklet-util-needs-directive-across-imports-2026-06-27.md`
