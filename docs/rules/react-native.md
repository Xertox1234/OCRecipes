# React Native Rules

- Never pass functions or callbacks as route params — use event params or navigate + read-and-clear in `useEffect` (non-serializable params break state persistence and deep links)
- Always call `navigation.goBack()` immediately after `navigation.navigate()` when dismissing a `fullScreenModal` — `navigate()` alone leaves the modal on the stack
- Touch targets must be ≥ 44pt — add `hitSlop` for small controls (e.g. `hitSlop={{ top: 8, bottom: 8, left: 8, right: 8 }}`)
- Always add `insets.bottom + Spacing.X` to the last-item padding in scrollable lists — bare `Spacing.X` clips content behind the home indicator on notched devices
- `KeyboardAvoidingView` behavior: `"padding"` on iOS, `"height"` on Android — never `undefined`
- Always spread `FLATLIST_DEFAULTS` from `@/constants/performance` on every `FlatList` — except horizontal carousels and short capped lists, which pass `removeClippedSubviews={false}` instead (clipped cells are unreachable by screen readers; see `docs/rules/performance.md`)
- Camera: always set `isActive={isFocused}` on `CameraView` — stops the camera when navigating away. Mic: always call `stopListening()` in session reset/cleanup — leaving it open mutates state after the component is gone
- `Alert.prompt` is iOS-only — guard with `Platform.OS === "ios"` and provide a `TextInput` fallback for Android
- Never gate `Linking.openURL(httpUrl)` behind `Linking.canOpenURL` — it returns false on iOS for HTTP(S) without `LSApplicationQueriesSchemes` entries. Call `openURL` directly and `try/catch` the failure
- A deep-link target screen must distinguish an **omitted** id param (the in-app create flow) from a **present-but-invalid** one. `linking.ts` `parseIntOrZero` coerces a malformed path segment to `0` and does not clamp negatives (`-5` parses to `-5`), so "malformed" is "present but not a positive integer". Deriving create-mode from a falsy check (`!entryId`) turns a bad link into a blank create form and a duplicate on save: derive create-mode from `param === undefined`, and for a present id that doesn't resolve render a **load-aware** not-found state (gate on the list query's `isLoading`/`isPending`, not just `!entry`). The malformed-id guard must also live INSIDE every side-effecting handler the id can reach, not only in the render branch — a mount/param-driven effect (e.g. a cross-tab auto-send-on-open) can invoke a create/send handler independently of what renders, and unparsed deep-link query params land in `route.params` unfiltered (see `linking.ts`'s `Scan`/`verifyBarcode` comment), so `chat/abc?initialMessage=hi` reaches the handler while the not-found view shows. Precedent: `client/screens/NotebookEntryScreen.tsx` (H4, 2026-05-29); `client/screens/ChatScreen.tsx` (M16, 2026-09-23) for the handler-level guard.
- A `beforeRemove` discard guard fires for the screen's OWN forward navigation too (`replace` removes the screen) — whitelist each intentional removal by `e.data.action.type` + payload target before `preventDefault()`, or the primary flow shows the discard confirm and can wipe state the destination reads. See `docs/solutions/logic-errors/before-remove-guard-intercepts-own-replace-2026-06-10.md`
- Scrollable content under a transparent header (`useScreenOptions()` defaults `headerTransparent: true`) takes its top inset from `useHeaderContentInset()` (`client/hooks/useHeaderContentInset.ts`) — or the `ScreenScrollView` wrapper (`client/components/ScreenScrollView.tsx`) for plain-`ScrollView` screens — never `useHeaderHeight` + hand-rolled `paddingTop`. Never use an iOS-only prop (`contentInsetAdjustmentBehavior`, `contentInset`) as the sole fix — it no-ops on Android and leaves the hidden-first-row bug live there. See `docs/solutions/logic-errors/ios-only-scroll-inset-prop-leaves-android-header-overlap-2026-07-02.md`
- A function imported from another module and called inside a Reanimated worklet body (`runOnUI`/`scheduleOnUI`, `useAnimatedStyle`, `useAnimatedScrollHandler`, a Gesture builder callback, …) needs its own `"worklet"` directive as its first statement — the Babel plugin does not workletize across `import` edges, and a missing directive is a silent app close in release/OTA builds that `tsc`/ESLint/unit tests all pass. Enforced by `scripts/__tests__/worklet-directive-guard.test.ts`; its `WORKLET_CALLBACK_HOOKS` set is name-keyed, so a new worklet-scheduling entry point must be added there too or the guard silently stops inspecting it. See `docs/solutions/runtime-errors/reanimated-worklet-util-needs-directive-across-imports-2026-06-27.md`
- Never wire a shared height-clamping shell's `maxHeight` through to a new consumer without checking that consumer's content is structurally bounded (fixed-size list, `.slice()`'d preview, or its own internal scroll) — an `overflow: "hidden"` clip with no internal `ScrollView` permanently hides content with no scroll affordance. If unbounded, keep `maxHeight` optional and omit it for that consumer. See `docs/solutions/logic-errors/shared-height-clamp-shell-needs-bounded-child-content-2026-09-25.md`
- A screen registered with `presentation: "modal"`/`"fullScreenModal"` that can open a gorhom `BottomSheetModal` (incl. `useConfirmationModal`) must carry `layout={withSheetProvider}` on its `Stack.Screen` — the only other provider sits above `NavigationContainer`, so on iOS the sheet renders UNDER the native modal (a full-screen modal's close confirm traps the user). Enforced by `scripts/__tests__/native-modal-sheet-provider.test.ts`. See `docs/solutions/logic-errors/bottom-sheet-from-native-modal-screen-renders-under-the-modal-2026-10-01.md`
