# Accessibility Rules

> Binding directives only; embedded whole on every a11y-domain edit (cap: `scripts/check-rules-file-size.js`). **Add new depth to the solution the bullet cites, not here.**

- All `fullScreenModal` and `modal` screens need `accessibilityViewIsModal={true}` on the root container — VoiceOver navigates behind the modal without it
- Decorative content (icons inside labeled Pressables, emoji in a `Text`, badges inside a parent with an `accessibilityLabel`) gets `accessible={false}` — otherwise VoiceOver double-focuses or reads it literally
- `Pressable` with `disabled={true}` auto-propagates to `accessibilityState.disabled` on RN 0.81 — an explicit `accessibilityState={{ disabled: true }}` is only required on NON-Pressable touchables (TouchableOpacity, custom Views)
- Error messages use `accessibilityLiveRegion="assertive"` not `"polite"` — use the `InlineError` component, not `Alert.alert()`
- Radio buttons: `accessibilityState={{ selected: bool }}` not `{{ checked: bool }}` (`checked` is checkbox semantics on TalkBack); radio chip rows need a `role="radiogroup"` wrapper `View`. iOS Fabric (`newArchEnabled: true`) drops the _wrapper_ announcement for `radiogroup`, `tablist` and other ARIA group roles; Android is unaffected. **Decision (2026-07-19): accept-and-document, do not mitigate** — per-item `radio` semantics still announce on both platforms, and an iOS-only cue can't be verified without a live device pass and risks double-announcing. Keep the wrapper, add no per-screen cues. Record: `docs/solutions/design-patterns/radio-checkbox-group-container-pattern-2026-05-13.md`
- Progress bars need `accessibilityRole="progressbar"` + `accessibilityValue={{ min: 0, max: 100, now: value }}`
- Never set `accessible={true}` on a banner/card wrapper that contains an interactive child (dismiss/CTA Pressable) — VoiceOver/TalkBack collapses children into one node and the button becomes unreachable. Put the role/label on the text node; let the Pressable stay its own a11y node
- Never apply `accessibilityRole="checkbox"` (or `"radio"`, `"switch"`) to a non-`Pressable` — assistive tech announces the toggle affordance but the gesture does nothing. For visual-only indicators set `accessible={false}` + `importantForAccessibility="no"` and roll the state into a parent group's `accessibilityLabel`
- `importantForAccessibility="no"` excludes ONLY the view it is set on — its subtree stays in the Android a11y tree, and a child's own `accessible={false}` does not save you. A decorative container WITH CHILDREN needs `"no-hide-descendants"` + `accessibilityElementsHidden` for iOS. Likewise `pointerEvents="none"`, `opacity: 0`, and `height: 0`+`overflow: hidden` do NOT remove a mounted view from the a11y tree — any visually-hidden-but-mounted surface also sets `accessibilityElementsHidden={hidden}` + `importantForAccessibility={hidden ? "no-hide-descendants" : "auto"}`; when two surfaces swap (expanded ⇄ collapsed) hide whichever is invisible, BOTH directions, and resync when `reducedMotion` changes visibility at runtime. Verify with `uiautomator dump --compressed` — the default dump cannot tell broken from fixed, and `focusable=false` is NOT evidence of exclusion. See `docs/solutions/conventions/a11y-hide-visually-hidden-surfaces-2026-06-10.md`, `best-practices/adb-uiautomator-ondevice-android-verification-2026-07-12.md`

Announcements — iOS imperative announce vs Android live region (the double-announce family):

- Traits alone NEVER announce on iOS: `accessibilityLiveRegion` is Android-only, and neither `accessibilityRole="alert"` nor `accessibilityState={{ busy: true }}` posts a VoiceOver announcement. Every async transition (success, error, limit-reached, pending) needs `AccessibilityInfo.announceForAccessibility` — never remove it thinking the alert role or busy trait covers iOS
- Never double-announce a platform: gate the imperative announce to `Platform.OS === "ios"` ONLY when the element still has an Android live region covering the same change; with no live region, announce on BOTH platforms ungated. `InlineError` fires its own iOS-gated announce — never add a second one in the `onError` handler that renders it
- Announce mutation errors from the `onError` handler (fires once per failure), not a `useEffect` keyed on `isError` (re-fires on stale re-renders); announce pending/busy on the idle→busy edge with a prev-value ref guard (silent on mount and on clear)
- A `"polite"` live region on a SHARED container wrapping a structural swap (e.g. `Text`↔`ActivityIndicator`) or a descendant's state change re-reads the ENTIRE subtree on every descendant change (TalkBack composes `CONTENT_CHANGE_TYPE_SUBTREE`). When one container is the sole announcer for several states, drop the container live region and announce imperatively per transition — keyed on the CONTENT that changed (an async-loaded name/value), not only the variant/discriminator, with a second edge-guarded effect keyed on that value. Precedent: `ProductChip.tsx`
